# 연구 준비

2026-11-05. 연구 질문과 평가 설계 초안이며 실험 결과나 논문 초고가 아니다.

## 질문 A: 개인 AI의 공공자료 조회

기관별 관계 설명과 질의 예제가 원하는 근거를 찾는 데 도움이 되는가?

먼저 동일한 원천과 질문, 모델, 도구 예산으로 범용 SPARQL MCP와 기관별 안내를 제공한 구현을 비교한다. 관계 설명, 질의 예제, 오류 안내를 하나씩 추가해 효과를 분리한다. 전부 넣은 결과를 온톨로지 효과라고 부르지 않는다.

공식 MCP는 지원 과제와 자료가 겹치는 경우에만 같은 조건의 성능 비교 대상으로 삼는다. 도서관 정보나루와 국가서지 LOD, HRDK와 워크넷처럼 원천이 다른 서비스는 기능 범위와 설치 부담을 별도로 비교한다. 공식 MCP가 제공하지 않는 자료를 묻고 이를 성능 실패로 집계하지 않는다.

현재 조회 로그에는 실행 ID, 프로그램 버전, 원문 URI, 질의, 조회 시각, 응답 해시, 상태와 시간이 포함된다. 응답 해시를 원천의 문서 버전으로 사용하지 않는다. LLM 모델 설정, 비용, 사람이 확인한 기대 근거와 답변 평가는 아직 수집하지 않았다.

## 질문 B: 팀 Wiki의 변경 유지

원문 버전과 Wiki 문장을 연결하면 오래된 설명을 찾고 수정하는 작업을 줄일 수 있는가?

전체 재생성, 문서 단위 재생성, 문장별 근거 추적을 비교한다. 문서 추가, 수치 수정, 삭제, 이동과 접근 철회를 시험한다. 필요한 변경을 놓친 수와 불필요하게 재검토한 수를 함께 평가한다. 기존 프로젝트의 동등 기능부터 확인하고 새 기여가 있는 부분을 분리한다.

## 평가 자료와 기록

- 질문과 기대 근거를 먼저 고정하고 성공 기준을 결과를 본 뒤 바꾸지 않는다.
- 기관, 시점 또는 과제 유형으로 평가 자료를 나눠 반복 템플릿의 누출을 줄인다.
- 성공, 빈 결과, 원천 오류, 잘못된 연결과 보류를 구분한다.
- 원천 데이터의 주장, 사람이 검증한 사실, 모델의 추론을 구분한다.
- 공개 또는 합성 자료부터 사용하며 팀의 비공개 문서와 인증정보는 공개 로그에 넣지 않는다.
- 해외 자료는 언어와 기관이 달라져도 방법이 유지되는지 검증할 필요가 생길 때 추가한다.

초기에는 두 질문을 준비하되 구현한 기여와 비교 결과가 분명한 쪽을 논문 주제로 좁힌다. 현재 첫 연결 시험은 방법론의 우수성이나 실제 사용자 효과를 입증한 결과가 아니다.
